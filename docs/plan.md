## 진행 원칙

1. **Phase는 하나씩 진행한다.** 만들고 → 직접 실행해서 확인하고 → 커밋한 뒤 다음 Phase로 넘어간다.
2. **Phase를 시작하기 전에 AI에게 먼저 묻는다.** 내가 준비할 값(API 키 등), 설치할 것, 정해야 할 것이 있는지.
3. **정확성이 먼저, 화면은 나중.** 재무 숫자가 DART 원문과 맞는지 확인한 뒤에 화면과 AI 해석을 붙인다.
4. **AI 해석은 데이터가 다 갖춰진 뒤에 붙인다.** AI에게 넘길 숫자와 원문이 먼저 있어야 한다.
5. 각 Phase가 끝나면 `docs/progress.md`에 완료한 것과 다음 할 일을 남긴다.

  - 기업 개요 보강: 직원 수·평균 근속연수·평균 급여(DART 직원 현황), 연구개발비 추출(AI 추출 + 원문 링크)과 매출 대비 비중 계산. 직원 현황은 사업보고서 기준(보통 별도)임을 표시, 최근 1개 연도, 평균 급여는 만 원 단위. 연구개발비는 정형 API가 없으면 사업보고서 "연구개발 활동"에서 AI 추출 (spec.md 5장)
  - 섹션별 한 줄 요약, 주석(의미·왜 중요한가·근거), 기업 개요, BCG 해석

- 확인: AI가 쓴 문장 속 숫자가 계산 결과와 같은지, 추출한 비중·연구개발비가 사업보고서 원문과 같은지, 직원 현황 값이 DART 화면과 같은지 직접 대조
- 커밋: `재무 해석과 주석 AI 연동`

### Phase 8-B. 화면 재구성 (1~4장 + 부록)

목적 재정의(기업분석을 쉽게 해서 자기소개서를 빨리 쓰게 돕기)에 따라 화면을 결론부터 보이게 바꾼다. **위치와 묶음만 바꾼다**: 백엔드 수집·계산·AI 호출(수·프롬프트·입력 자료)·DB는 바꾸지 않는다.

- 할 일
  - 리포트 화면을 spec.md F4 순서로: 1장 회사 한눈에 → 2장 지금 회사의 이슈 → 3장 강점과 과제 → 4장 나와의 연결 → 부록 A~E. 기존 섹션 컴포넌트는 그대로 옮겨 쓴다
  - 나눠지는 섹션: 경쟁사 비교의 위치 문장·시가총액 순위를 1장 업계 위치로, 종합 평가의 한 줄 평가(1장)와 SWOT(3장), 과제·역량(3장)과 직무별 기여(4장), 비교표의 PER·PBR 설명을 부록 D로
  - 4장 "예상 면접 질문": 기존 지켜볼 점·생각해볼 질문을 제목과 순서만 바꿔 표시(AI 호출 그대로)
  - 4장 "자기소개서에 쓸 숫자 모음": 저장된 계산 결과·검증된 추출값에서 코드가 고른 한 줄 사실 + 출처 링크, 값이 없는 항목은 빼고 이유 표시 (spec.md 3장, 9줄)
  - 코멘트 키 2개 추가: `tasks`(3장 회사의 과제), `essay_numbers`(4장 숫자 모음). 기존 키는 그대로(`swot`은 3장 SWOT, `page4`는 4장 직무별 기여)
  - 1장은 종합 한 줄 평가 + 핵심 지표 카드를 맨 위에
  - 부록 접힘: 기본 접힘, 제목·한 줄 요약은 접힌 상태에서도 보임, 섹션별 펼치기·[모두 펼치기]/[모두 접기], 접힌 섹션에 "코멘트 있음", 접어도 내용은 지우지 않고 숨김(쓰던 코멘트·저장 안 함 경고 유지), 1~4장의 근거 링크로 해당 부록 섹션 펼치고 이동
  - 근거 섹션 이름을 새 위치로 표시("2페이지 현금흐름 패턴" → "부록 C 현금흐름 패턴" 등). 근거 키·AI 입력 자료 이름은 그대로
  - 화면 문구의 "N페이지"를 "N장/부록"으로 (예: SWOT의 "(1~3페이지 분석 기반)")
  - 숫자 모음 문장 만들기 함수에 자동 테스트(값 있음·해당 없음·시세 없음·AI 추출 미검증·별도 기준)
  - `docs/design.md`의 페이지별 적용 원칙을 1~4장 + 부록 기준으로 다시 맞춘다(진행 중인 1페이지 디자인 정리를 1장에 이어서 적용)
- 내가 할 일: 브라우저로 확인 (숫자 모음 항목·1장 순서·부록 접힘 방식·코멘트 키는 2026-11-03 확정)
- 확인: 기존 리포트(SK하이닉스 10번)를 열어 모든 섹션이 새 위치에 빠짐없이 있는지(대응표 기준), 기존 코멘트가 같은 섹션에 그대로 보이는지, 숫자 모음의 숫자가 다른 섹션에 보이는 값과 같은지·링크가 맞는지, 부록을 접었다 펴도 쓰던 코멘트가 남는지, 리포트를 열 때 AI 호출이 없는지, 네이버 검색결과 앞뒤에 다른 내용이 붙지 않는지
- 커밋: `리포트 화면을 1~4장과 부록으로 재구성`

상태(2026-11-03): 구현과 자동 확인은 끝났고 사용자 브라우저 확인·커밋 전이다. 바로 뒤에 방향을 조정했으므로(8-C~8-E) 8-B의 화면 순서는 8-E에서 다시 바뀐다. 8-B에서 만든 부록 접힘·리포트 안 이동·근거 이름 바꾸기·숫자 모음·직무별 기여 표는 8-E에서 그대로 쓴다

### Phase 8-C. PDF 입력 (기업 검색 → PDF 올리기 → 리포트 생성)

방향 조정(spec.md v0.5): 서술 내용은 사용자가 올린 PDF에서, 재무 숫자는 DART API에서. 이 Phase는 **PDF를 받아 확인하고 섹션으로 나눠 저장하는 것까지**(AI 없음).

- 할 일

  - PDF 텍스트 추출과 섹션 나누기(목차 제목 기준, 쪽 범위 저장, 섹션당 길이 상한). 저장: 파일 이름·해시·쪽수·확인 결과·섹션 텍스트(원본 파일은 저장하지 않음 — spec.md 6장 정할 것 5)
  - 생성 흐름: 경쟁사 선택 화면을 흐름에서 빼고(코드 유지) 경쟁사 0곳으로 생성. 주가·시가총액·PER·PBR은 분석 기업만 수집·계산(지금은 경쟁사 비교 계산 안에 있으므로 분석 기업만으로 계산되게 맞춤). 생성 단계에 "PDF 읽기" 추가
  - PDF 라이브러리 고르기(spec.md 6장 확정 11), `requirements.txt`에 추가
  - 자동 테스트: 확인 규칙 5개(맞음·종류 다름·회사 다름·연도 다름·스캔본), 섹션 나누기(목차 찾음·못 찾음), 숫자 대조(일치·불일치·못 찾음). 테스트용 PDF는 작은 고정 파일로 만든다(실제 사업보고서 PDF는 저장소에 넣지 않음)
- 내가 할 일: DART 공시뷰어에서 SK하이닉스 2025 사업보고서·2026 반기보고서 PDF, 다른 회사 사업보고서 PDF 1개를 받아 두기(경로만 알려주기, 저장소에는 넣지 않음)

- 커밋: `사업보고서 PDF 올리기와 확인 구현`

  - 옮기는 섹션: 실적 추이 → 2장, 현금흐름·회계 이슈 → 4장, "순이익이 영업이익보다 큰 이유" → 4장 일회성 이익, 연구개발비 → 3장, 네이버 검색결과 → 부록 E(마지막 독립 섹션)

### Phase 9. Supabase 전환

- 할 일
  - SQLite → Supabase(PostgreSQL), 연결 정보는 `.env`에서 읽기 (Session pooler)
  - Alembic으로 명령 하나에 테이블 생성, 이미 적용한 변경은 다시 적용하지 않기
  - 설정이 없거나 잘못되면 확인할 점 안내, SQLite로 자동 연결하지 않기
  - 기존 SQLite 파일은 삭제하지 않음 (데이터 이전은 하지 않음)
- 내가 할 일: Supabase 프로젝트 생성, 연결 정보를 `.env`에 직접 입력, 테이블 생성 명령 실행
- 확인: 서버 재시작 후 리포트 생성 → Supabase 화면에서 데이터 확인
- 커밋: `Supabase(PostgreSQL) 연동`
