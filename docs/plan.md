# PLAN (개발 계획) — 기업분석 리포트 툴 (가칭)

> 문서 상태: 초안 v0.2 (2026-11-02) — 4페이지·주식시세·기업 개요 보강 반영
> 바탕 문서: `docs/spec.md` v0.3
> 기술 스택: 프론트 React / 백엔드 Python FastAPI / DB 개발 중 SQLite → 마지막에 Supabase(PostgreSQL)

---

## 진행 원칙

1. **Phase는 하나씩 진행한다.** 만들고 → 직접 실행해서 확인하고 → 커밋한 뒤 다음 Phase로 넘어간다.
2. **Phase를 시작하기 전에 AI에게 먼저 묻는다.** 내가 준비할 값(API 키 등), 설치할 것, 정해야 할 것이 있는지.
3. **정확성이 먼저, 화면은 나중.** 재무 숫자가 DART 원문과 맞는지 확인한 뒤에 화면과 AI 해석을 붙인다.
4. **AI 해석은 데이터가 다 갖춰진 뒤에 붙인다.** AI에게 넘길 숫자와 원문이 먼저 있어야 한다.
5. 각 Phase가 끝나면 `docs/progress.md`에 완료한 것과 다음 할 일을 남긴다.

### Phase 5. 경쟁사 비교 (5-A / 5-B로 나눠 진행)

공공데이터포털 키 활성화를 기다리는 동안 DART만으로 되는 부분(5-A)을 먼저 만들고, 주식시세는 키가 활성화된 뒤(5-B) 붙인다.

#### 5-A (DART 재무만)

- 할 일
  - 경쟁사 자동 추천(같은 업종코드 후보 최대 8곳)은 **나중으로 미룸**. 기업명 직접 검색 추가만 사용하고, 1~4곳 선택 제한. 경쟁사 선택 화면은 생성 전에 거친다 (검색 → 기업 선택 → 경쟁사 선택 → 리포트 만들기)
  - 경쟁사 재무 수집·계산 (Phase 2 재사용), 데이터 부족 시 제외 표시
  - 비교표 5개 지표(매출액, 매출액증가율, 영업이익률, ROE, 부채비율): 평균(분석 기업 포함) 대비 ▲▼, 순위(부채비율은 낮을수록 1위), 성장률×이익률 점 그래프, 업계 내 위치 한 줄
  - 비교표 열은 지표 정의 목록(`app/comparison.py`의 `COLUMN_DEFS`)에서 나오게 만들어, 5-B에서 정의만 추가하면 열이 늘어나게 한다 ("준비 중" 자리는 만들지 않음)
- 내가 할 일: 없음 (DART 키만 사용). 확인용 경쟁사로 삼성전자·DB하이텍 선정 완료
- 확인: 비교표 숫자를 DART 원문(또는 Phase 2에서 대조한 값)과 비교, 순위·▲▼·위치 문장이 표와 맞는지
- 커밋: `경쟁사 선택과 재무 비교 구현 (Phase 5-A)`

#### 5-B (공공데이터포털 키 활성화 후)

- 할 일
  - 주가·시가총액 수집 → PER·PBR 계산, 분석 기업·경쟁사의 최근 1년 일별 주가 수집
  - 비교표에 시가총액(경쟁사 중 순위, 큰 순서 1위)·PER·PBR(순위 없이 평균 대비 높음·낮음만) 열 추가 (5-A의 지표 정의 목록에 정의를 더한다)
  - 주가 흐름 비교 선 차트 (기업마다 1년 전 기준일 = 100), 차트 아래에 "수정주가가 아님" 한계 문구 표시. 기사 날짜 표시는 Phase 7에서 연결
- 내가 할 일: 공공데이터포털 회원가입, 금융위원회 주식시세정보 활용 신청, 키를 `.env`에 입력. 시가총액 항목이 있는지, 최근 1년 일별 시세를 기간으로 조회할 수 있는지, 호출 한도 안인지 확인 (spec.md 6장 확인 필요 4)
- 확인: 같은 업종 기업 2곳의 PER·PBR을 증권사 앱·포털 수치와 비교 (기준일 차이 감안), 주가 차트의 1년 전 기준일과 마지막 날 값이 포털 주가 차트와 같은 방향인지 확인 (액면분할 기업은 왜곡 가능)
- 커밋: `주식시세 비교 구현 (Phase 5-B)`

### Phase 6. AI 해석 1: 재무

6-A(AI 연결·추출·해석·화면, 가짜 응답으로 구현 완료·실제 호출 확인 전)와 6-B(회계 이슈 체크: 감사의견은 먼저 OpenDART 정형 API로 AI 없이 받을 수 있는지 확인, 계속기업 불확실성·특수관계자 거래만 AI 추출, 6-A 확인 후)로 나눈다. 아래 "회계 이슈" 항목은 6-B.

- 할 일
  - AI 연결(`LLM_PROVIDER`로 OpenAI/Claude 선택, 기본 OpenAI)을 AI 호출 모듈 한 곳에 모으기, AI에게 주는 규칙 정하기: 넘겨준 자료 안에서만, 숫자 만들지 않기, 근거 없으면 "자료 없음"
  - 회계 이슈: 공시 목록에서 정정공시 확인, 사업보고서에서 감사의견·계속기업 불확실성·특수관계자 거래 확인
  - 사업부문 매출 비중·수출 비중 AI 추출 + "AI 추출" 표시 + 원문 링크
  - 기업 개요 보강: 직원 수·평균 근속연수·평균 급여(DART 직원 현황), 연구개발비 추출(AI 추출 + 원문 링크)과 매출 대비 비중 계산. 직원 현황은 사업보고서 기준(보통 별도)임을 표시, 최근 1개 연도, 평균 급여는 만 원 단위. 연구개발비는 정형 API가 없으면 사업보고서 "연구개발 활동"에서 AI 추출 (spec.md 5장)
  - 섹션별 한 줄 요약, 주석(의미·왜 중요한가·근거), 기업 개요, BCG 해석
  - 화면: 주석 ⓘ 펼치기·접기(F5), "AI 작성" 표시, 1페이지 사업부문 차트
- 내가 할 일: OpenAI 키를 `.env`에 입력(부서 공유 키, 사용 허락 확인)
- AI 사용 규칙(spec.md 0장 규칙 9): 개발 중 AI 호출 테스트는 SK하이닉스 1곳으로만, 같은 리포트의 해석은 다시 만들지 않음
- 확인: AI가 쓴 문장 속 숫자가 계산 결과와 같은지, 추출한 비중·연구개발비가 사업보고서 원문과 같은지, 직원 현황 값이 DART 화면과 같은지 직접 대조
- 커밋: `재무 해석과 주석 AI 연동`

  - PEST, 5 Forces, 기사 주제 묶음 3개(관련 기사 링크 포함), 환율 10% 상승 시 영향 방향, 지켜볼 점·질문
  - 마지막으로 SWOT과 종합 한 줄 평가 (1~2페이지 결과까지 모두 넘겨서)
  - SWOT 다음에 4페이지 "회사의 과제와 나의 기여": 1~3페이지 결과(SWOT 약점·위협, 기사 주제, 신호등, 민감도, 현금흐름)에서 과제 3개(근거 섹션 표시), 과제별 필요한 역량 1줄, 직무 4개 기여 아이디어 1줄씩. "분석 기반 제안"·"AI 작성" 표시와 공식 인재상 아님 안내. 자기소개서 문장은 쓰지 않음
  - 기사 주제 날짜를 Phase 5의 주가 흐름 차트 날짜 축에 표시 (spec.md 5장)
  - 화면: 3·4페이지 완성, 1페이지 SWOT·종합 평가
- 내가 할 일: NAVER API HUB 키는 발급·입력 완료(유료 전환 여부만 콘솔에서 확인), ECOS 인증키 신청, `.env`에 입력
- 확인: 기사 요약의 링크가 실제 기사로 연결되는지, 환율·금리 값이 한국은행 수치와 같은지, 4페이지 과제의 근거 섹션이 실제로 그 내용을 담고 있는지·자기소개서식 문장이 없는지
- 커밋: `외부 환경 분석, SWOT, 과제·기여 구현`

### Phase 9. Supabase 전환

- 내가 할 일: Supabase 프로젝트 생성, 연결 정보를 `.env`에 직접 입력, 테이블 생성 명령 실행
