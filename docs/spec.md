## 0. 공통 규칙

1. **숫자는 코드가 계산한다.** AI에게는 계산이 끝난 숫자와 원문 자료만 넘기고, AI는 해석·요약·주석 문장만 쓴다.
2. **AI는 넘겨받은 자료 안에서만 쓴다.** 자료에 없는 사실·숫자를 만들지 않고, 근거가 없으면 "자료 없음"이라고 쓴다.
3. **출처를 붙인다.** 수치·주석·요약마다 원문 링크(DART 공시 원문, 기사 URL, 한국은행 통계)를 저장하고 보여준다.
4. **AI가 쓴 부분은 "AI 작성" 표시**를 붙인다.
5. 숫자 표시는 아래 **"숫자 표시 규칙"** 하나로 통일한다. 금액은 카드 조 원·표 억 원, 비율은 소수점 첫째 자리 %. (예외: 평균 급여는 만 원)
6. 재무제표는 **연결재무제표를 우선**하고, 연결이 없으면 별도재무제표를 쓰며 어느 쪽인지 표시한다.
7. 기간은 **최근 5개 사업연도(연간, 사업보고서 기준)**.
8. **AI 호출은 코드 한 곳(모듈 하나)에 모은다.** 제공자는 `.env`의 `LLM_PROVIDER`(`openai` 또는 `anthropic`, 기본 `openai`)로 고르고, 제공자를 바꿔도 나머지 코드는 그대로 둔다.
9. **AI 사용량을 아낀다.** OpenAI 키는 부서 공유 키라 사용량 한도를 직접 걸 수 없을 수 있다. 개발 중 AI 호출 테스트는 **SK하이닉스 1곳으로만** 하고, **같은 리포트의 해석은 다시 만들지 않는다** (한 번 만들어 저장한 해석은 저장본을 그대로 쓰고, 리포트를 열 때는 AI를 호출하지 않는다. 실패한 단계의 [다시 시도]는 실패한 호출만 다시 보낸다).
10. **네이버 검색결과(기사)는 AI에 넣지 않는다.** NAVER 검색 API 약관(검색 API 특약 2.1~2.4, 2026-10-07 개정 NAVER Developers 판 기준)이 검색 데이터와 그 가공·파생물을 AI에 입력·학습·노출하는 것을 금지한다. 기사는 부록 E "네이버 검색결과" 참고 목록으로만 받은 그대로 보여주고(검색어 강조 `<b>`는 굵은 글씨로만 표시, 다른 태그는 허용하지 않음), 서버에는 수집 후 **21일**까지만 보관한다. 외부 환경 AI 해석의 입력은 DART 공시·사업보고서(올린 PDF 포함), ECOS 지표, 코드 계산 결과만 쓴다
11. **서술 내용은 올린 PDF에서, 원문 인용 검증을 거친다** (2026-11-03). 사업의 내용·이사의 경영진단 및 분석의견·위험·경쟁 현황·연구개발 같은 서술은 사용자가 올린 사업보고서(필수)·반기/3분기보고서(선택) PDF에서 읽는다. AI는 요약과 함께 원문 인용을 돌려주고, 코드가 인용이 PDF 텍스트에 실제로 있는지 확인해 없으면 버리고 쪽 번호를 붙인다(F4 "PDF 원문 인용 규칙"). 재무 숫자는 PDF에서 읽지 않고 DART API 값을 쓴다
12. **경쟁사 데이터는 끌어와 비교하지 않는다** (2026-11-03). 경쟁사 재무 수집·비교표·점 그래프·주가 비교는 화면과 생성 흐름에서 빼고 코드는 지우지 않는다

### 숫자 표시 규칙 (화면 공통, 2026-11-02 추가)

화면의 모든 숫자는 프론트엔드의 변환 함수 한 곳(`frontend/src/format/`)을 거쳐 표시한다. 저장값은 바꾸지 않는다(금액은 DART 원문 그대로 원 단위 정수, 비율은 소수 0.123 = 12.3%).

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 금액 (카드) | **조 원**, 소수 첫째 자리. 절댓값이 0.1조 원 미만이면 "0.0조"로 보이지 않도록 억 원(쉼표)으로 대신 표시 | 53.4조 원 |
| 금액 (표) | **억 원**, 정수, 천 단위 쉼표. 단위는 셀이 아니라 **표 제목에 표시** | 제목 "(단위: 억 원)", 셀 971,467 |
| 음수 | 앞에 **− 기호**(U+2212)를 붙이고 **빨간색**. 반올림해서 0이 되면 음수로 표시하지 않음 | −77,303 |
| 비율 | **소수 첫째 자리 %** | 28.9% |
| 증감 | 매출·이익 등의 증감률은 **+/− 부호가 붙은 %**, 비율끼리의 차이(예: 영업이익률 변화)는 **%p** | +230.8%, +32.6%p |
| 환율·기준금리 | 환율은 **소수 첫째 자리 + 원**, 기준금리는 0.25%p 단위로 움직이므로 **소수 둘째 자리 %** (2.75%가 2.8%로 보이지 않게) | 1,337.2원, 2.75% |
| 배수 | 회전율·이자보상배율·재무레버리지는 %가 아니라 **배**, 소수 첫째 자리 | 3.8배 |
| 표 안의 숫자 | **오른쪽 정렬**, 숫자 폭이 같은 글꼴(tabular-nums) | |
| 신호등 | **초록·노랑·빨강 색 + "양호·주의·위험" 글자를 함께** 표시 (색만으로 구분하지 않음). 판정 이유는 마우스를 올리거나 옆 작은 글씨로 | ● 양호 |
| 해당 없음 | 계산할 수 없는 값은 **이유와 함께** 표시, 회색 글자 | 해당 없음(적자), 해당 없음(전기 자료 없음) |
| 자료 없음 | 수집하지 못한 값(이유를 따로 받지 못한 경우) | 자료 없음 |
| 평균 대신 기말 값 | 첫 연도처럼 평균을 못 내 기말 값만 쓴 비율은 숫자 뒤에 `†`를 붙이고 표 아래에 "† 평균 대신 기말 값 기준"을 표시 | 15.4%† |

- 이유 문구("적자", "전기 자료 없음" 등)는 백엔드 계산 결과가 주는 문구를 그대로 쓰고, 프론트가 새로 만들지 않는다.
- 이자비용 대신 금융비용으로 계산한 경우, 이자보상배율 이름을 "이자보상배율(금융비용 기준)"으로 표시하고 외환·파생상품 손실이 포함될 수 있다는 안내를 붙인다.

## 2. 기능별 동작

### F1. 기업 검색·선택

| 구분 | 내용 |
| --- | --- |
| 입력 | 기업명 (일부만 입력해도 됨, 예: "삼성전") |
| 동작 | 입력값이 포함된 **상장기업**을 찾아 목록으로 보여준다 (최대 10개) |
| 목록에 보이는 것 | 기업명, 종목코드, 업종 |
| 결과 | 기업 하나를 누르면 F2 PDF 올리기로 넘어간다 (2026-11-03 방향 조정: 경쟁사 선택 단계 없음) |

조건과 예외
- 2글자 미만이면 검색하지 않고 "2글자 이상 입력해 주세요" 안내
- 기업명에 "스팩" 또는 "기업인수목적"이 들어간 기업(기업인수목적회사)은 검색 결과에서 뺀다
- 정렬: 이름이 검색어와 같은 기업 → 검색어로 시작하는 기업 → 검색어를 포함하는 기업 순이고, 같은 순위 안에서는 이름이 짧은 순(대표 기업이 앞에 오도록), 그다음 가나다순
- 상장 일반 결과가 10개를 넘으면 앞의 10개만 보여주고 "결과가 많습니다. 더 정확한 이름으로 검색해 주세요" 안내
- 검색 결과가 없으면 "상장기업 중 일치하는 기업이 없습니다" 안내 (비상장기업도 이 안내)
- 금융업(은행·증권·보험 등 업종코드)이면 목록에는 보이되 선택 시 "현재 버전은 일반기업만 분석합니다" 안내 후 진행하지 않음

### F2. 보고서 PDF 올리기·확인 (2026-11-03 방향 조정, 구 F2 경쟁사 선택을 대신함)

| 구분 | 내용 |
| --- | --- |
| 입력 | F1에서 고른 기업 + **사업보고서 PDF(필수)** + **반기 또는 3분기보고서 PDF(선택)** |
| 안내 | 올릴 보고서를 코드가 미리 알려준다: "2025 사업보고서(2026-03-17 제출)"처럼 DART 공시 목록에서 찾은 **기준 사업연도 N의 사업보고서**와, 있으면 N+1년의 최근 반기/3분기보고서. DART 공시뷰어 원문 링크와 "뷰어의 [다운로드]에서 PDF를 받으세요" 안내 |
| 동작 | 파일을 고르면 바로 서버로 보내 **확인**한다(아래 "PDF 확인 규칙"). 결과를 칸마다 "확인됨 ✓ / 다시 올려 주세요 ✗ + 이유"로 보여준다 |
| 결과 | 사업보고서가 "확인됨"이면 [리포트 만들기]가 켜지고, 누르면 F3 시작 |

PDF 확인 규칙 (2026-11-03 확정)
- 코드가 PDF 텍스트에서 확인한다(AI 없음). DART는 PDF를 API로 주지 않아 원본과 파일을 직접 비교할 수 없으므로, **표지 내용 + 재무 숫자 대조**로 확인한다
- ① **글자를 읽을 수 있는가**: 앞 5쪽에서 텍스트가 나오지 않으면(스캔본·이미지) 거절 "글자를 읽을 수 없는 PDF입니다. DART 공시뷰어에서 받은 PDF를 올려 주세요" (OCR은 하지 않음)
- ② **보고서 종류**: 표지(책갈피 중 제목이 "사업보고서·반기보고서·분기보고서"인 쪽, 책갈피가 없으면 앞 10쪽 중 "사업연도"가 있는 첫 쪽. 글자 사이 띄어쓰기를 지우고 비교. DART PDF는 1~3쪽이 목차라 표지가 4쪽이고, 정정 보고서는 목차 4쪽 + "정정신고(보고)" + 확인서 뒤라 7쪽 — 2026-11-03 실제 PDF로 확인해 고침)의 제목이 칸과 맞아야 한다 — 사업보고서 칸은 "사업보고서", 선택 칸은 "반기보고서" 또는 "분기보고서"(3분기). 1분기보고서는 거절. 제목에 "[기재정정]"이 있거나 앞에 "정정신고(보고)"가 붙어 있으면 받되 "정정 보고서" 표시
- ③ **회사**: 표지 "회사명" 줄의 이름이 DART 기업개황의 정식 회사명과 같아야 한다(띄어쓰기·"주식회사"·"(주)"를 지우고 비교. 예: 표지 "에스케이하이닉스 주식회사" = 기업개황 정식 명칭. 종목명 "SK하이닉스"와는 다를 수 있어 종목명만으로 비교하지 않음)
- ④ **기간**: 표지 "사업연도 ○○년 ○○월 ○○일 부터 ○○년 ○○월 ○○일 까지"가 맞아야 한다 — 사업보고서는 N년 1월 1일~12월 31일, 반기는 N+1년 1월 1일~6월 30일, 3분기는 N+1년 1월 1일~9월 30일(12월 결산 가정, 6장 확인 필요 6과 같음). 다른 연도면 "이 PDF는 2024 사업보고서입니다. 2025 사업보고서를 올려 주세요"
- ⑤ **숫자 대조(경고만)**: PDF "III. 재무에 관한 사항 – 요약재무정보"에서 당기 매출액(사업보고서) 또는 당기 누적 매출액(반기/3분기)을 찾아 DART API 값과 같은지 본다(백만 원 단위 반올림 허용). 같으면 "재무 숫자 일치", 못 찾거나 다르면 노란 경고 "재무 숫자를 대조하지 못했습니다"만 보여주고 진행은 막지 않는다(표 글자가 깨져 못 찾는 경우가 있어서)
- ①~④ 중 하나라도 맞지 않으면 그 칸은 거절(저장하지 않음)하고 이유를 보여준다. 같은 파일을 두 칸에 올리면 거절
- 크기 한도: 파일당 50MB

PDF를 올리지 않으면 (2026-11-03 확정: **필수 유지, DART 원문으로 자동 대체하지 않음**)
- 사업보고서 PDF가 확인되지 않으면 [리포트 만들기]를 누를 수 없다. 반기/3분기 PDF는 없어도 된다(해당 보충 내용만 "올리지 않음")
- 이유: 서술 내용의 인용·쪽수 표시가 PDF 하나를 기준으로 맞춰지고, 추출 경로가 둘이면 검사·가짜 응답·테스트가 두 벌이 된다. 사업보고서 PDF는 DART 공시뷰어에서 바로 받을 수 있다
- 예외: 이 기능 전에 PDF 없이 만든 리포트는 그대로 열린다(PDF 기반 섹션은 "PDF 없이 만든 리포트입니다. 새로 만들면 표시됩니다")

구 F2 경쟁사 선택 (화면에서 숨김, 코드 유지)
- 경쟁사 선택 화면·경쟁사 재무 수집·비교표·점 그래프·경쟁사 주가 비교는 **화면과 생성 흐름에서 빼고 코드는 지우지 않는다**. 새 리포트는 경쟁사 없이 만든다(경쟁사 0곳). 예전 리포트에 저장된 경쟁사 비교 결과도 화면에 보이지 않는다

PDF에서 읽는 섹션 (DART 사업보고서 목차는 기업마다 같은 틀이다)

| 쓰는 곳 | 사업보고서 목차 | 비고 |
| --- | --- | --- |
| 1장 주력 사업 | II-1 사업의 개요, **II-2 주요 제품 및 서비스** | 주요 제품·매출 비중 표, 가격 변동 추이 (2026-11-03 추가). 주력 사업 설명 2~3문장의 재료 |
| 1장 업계 위치, 4장 고객 의존도 | II-1 사업의 개요, II-4 매출 및 수주상황, II-7 기타 참고사항(산업의 특성·경쟁 요소·시장점유율) | 경쟁사 이름·점유율 문장, 주요 고객 매출 비중 문장 |
| 2장 회사 스스로의 진단 | **IV. 이사의 경영진단 및 분석의견** | 사업보고서만. 반기·분기보고서에는 기재하지 않는 항목이다("기업공시서식 작성기준에 따라 반기보고서에는 본 항목을 기재하지 아니하였습니다", SK하이닉스 2026 반기보고서 원문에서 확인) |
| 3장 연구개발 | II-6 주요계약 및 연구개발활동 | 연구개발비 금액·비중은 지금처럼 DART 원문 추출 + 코드 계산 |
| 3장 투자·신규 시설 | II-3 원재료 및 생산설비(설비투자 현황) | |
| 3장 신사업 | II-1 사업의 개요, II-7 기타 참고사항(신규사업 등) | |
| 4장 회사가 밝힌 위험 요인 | II-5 위험관리 및 파생거래, II-7 기타 참고사항, IV 경영진단 중 위험을 말한 부분 | 사업보고서에는 "위험 요인"이라는 별도 목차가 없다(증권신고서 항목). 회사가 위 목차에서 직접 밝힌 위험만 인용한다 |

- 섹션 나누기는 코드가 목차 제목(로마 숫자·번호 + 제목)으로 한다. PDF에 들어 있는 **책갈피(목차와 쪽 번호)를 먼저 쓰고**(책갈피가 가리키는 쪽에 제목이 없으면 다음 쪽에서 찾는다 — 책갈피가 앞쪽 맨 아래를 가리키는 경우가 있음, LG 2025 사업보고서 II-3 55→56쪽), 책갈피가 없으면 본문의 제목 줄(목차 쪽의 점선 줄 제외, 장 제목은 쪽 첫 줄)로 찾는다. 같은 쪽 안의 시작·끝은 제목 줄 위치로 자른다(2026-11-03 확정)
- 쪽 번호는 **PDF 뷰어의 쪽 번호**로 저장·표시한다. DART PDF는 인쇄된 쪽 번호("Page N")보다 3 크다(1~3쪽이 목차). 섹션 글자는 쪽 번호와 함께 저장한다(꼬리말 "전자공시시스템 dart.fss.or.kr Page N" 줄은 뺀다)
- 섹션을 찾지 못하면 그 섹션을 쓰는 화면에 "사업보고서에서 이 항목을 찾지 못했습니다"
- AI에 넘기는 길이는 섹션마다 상한을 둔다(섹션당 12,000자, 넘으면 앞부분만 넘기고 "일부만 사용" 표시). 저장은 전체를 하고 넘는지만 표시하며, 자르는 것은 AI에 넘길 때(8-D) 한다. SK하이닉스 2025 사업보고서는 II-7 기타 참고사항(20,453자)만 넘는다

조건과 예외
- 상장 5년 미만: 있는 연도만으로 계산하고, 리포트에 "N년 자료만 있음" 표시
- 기사가 0건: 네이버 검색결과 섹션에 "검색결과 없음", 나머지는 정상 생성
- 기사 보관 기간(수집 후 21일)이 지남: 기사를 지우고(서버 시작 시·1시간마다·리포트를 열 때) 섹션에 "21일이 지나 기사를 지웠습니다"와 [다시 불러오기]를 보여준다. [다시 불러오기]는 회사명으로 다시 검색해 기사 목록만 바꾼다(AI 해석은 다시 만들지 않음)
- 한 단계가 실패하면 **어느 단계에서 실패했는지** 보여주고 [다시 시도] 버튼 제공. 실패한 리포트는 저장하지 않음
- PDF에서 섹션을 읽지 못해도(목차를 못 찾음) 리포트는 만들고, 해당 섹션만 "찾지 못함"

### F4. 리포트 보기

| 구분 | 내용 |

#### 화면 순서의 원칙 (2026-11-03 방향 조정)

- 리포트의 목적은 **기업분석을 쉽게 해서 취업 준비생이 자기소개서를 빨리 쓰게 돕는 것**이다. 내용은 두 축으로 묶는다: **"지원자가 알아야 할 것"**(1~3장)과 **"주의해서 볼 것"**(4장). 5장은 그 둘을 나와 연결한다
- 분석 논리(Top-down)는 안쪽 구조로 유지하고 근거가 되는 심화 분석은 부록에 둔다
- **경쟁사 데이터는 끌어와 비교하지 않는다.** 업계 위치는 사업보고서에서 회사가 직접 밝힌 경쟁사 이름·점유율 문장을 원문 인용으로만 보여준다
- **새 섹션의 서술은 사용자가 올린 PDF에서**, 재무 숫자는 지금처럼 DART API에서 가져온다. AI는 원문 인용 검증을 거친 해석만 쓴다
- **기존 내 코멘트는 잃지 않는다.** 모든 기존 키가 새 위치의 섹션에 그대로 붙는다(아래 대응표, DB 이전 없음)
- 섹션 공통: 맨 위 한 줄 요약, 맨 아래 내 코멘트란. 예외: 네이버 검색결과(약관상 코멘트란 없음), 숫자 모음(AI가 없으므로 한 줄 요약 없음), 1장 종합 한 줄 평가·4장 체크리스트 한눈에(코멘트란 없음)

PDF 원문 인용 규칙 (새 섹션 공통)
- AI는 요약 문장과 함께 **원문 인용**(PDF 텍스트에서 그대로 옮긴 문장)을 돌려준다. 코드가 인용이 해당 섹션 텍스트에 실제로 있는지(띄어쓰기·줄바꿈만 무시하고 비교) 확인하고, **없는 인용은 버린다**. 인용이 하나도 남지 않은 항목은 버린다
- 남은 인용에는 코드가 **쪽 번호**와 보고서 이름("2025 사업보고서 p.143")을 붙이고, DART 공시뷰어 원문 링크를 붙인다(PDF 파일 자체는 링크하지 않음)
- 요약 문장의 숫자는 그 항목의 인용이나 넘겨준 계산 결과에 있는 숫자만 허용한다(지금의 숫자 검사와 같음). 경쟁사 이름은 인용 안에 있는 이름만 남긴다
- "AI 작성" 표시와 함께, 인용은 회사가 쓴 문장임을 따옴표·회색 출처로 구분한다

근거 섹션 이름 표시
- 화면의 근거 이름은 새 위치로 표시한다(예: "부록 C 현금흐름 패턴" → "4장 현금흐름", "2장 공시 주제 2" → "3장 공시 주제 2", "3장 SWOT 약점" → "5장 SWOT 약점"). 근거 키와 AI 입력 자료 이름은 바꾸지 않고 화면에서 키로 바꿔 붙인다(8-B와 같은 방식)

조건과 예외 (4장 회계 이슈 체크, Phase 6-B)
- **상태는 세 가지**: 이상 없음 / 확인 필요 / **확인 불가(원문과 대조하지 못함)**. 자료를 받지 못했거나, AI 값을 원문과 대조하지 못했거나, 아직 만들지 않은 항목은 "이상 없음"이 아니라 "확인 불가"로 표시한다
- 감사의견(코드): 당기 행(별도·연결)이 모두 "적정의견"이면 이상 없음, 하나라도 다르면(한정·부적정·의견거절) 확인 필요(더 나쁜 쪽). 감사인·강조사항·핵심감사사항을 함께 보여준다
- 정정공시(코드): 기준 사업연도 다음 해 1월 1일~오늘의 정기공시 중 "정정"이 든 것이 1건 이상이면 확인 필요, 목록과 원문 링크 표시. "정정은 단순 오기 수정도 많다"는 안내를 붙인다
- 계속기업 불확실성: 감사보고서 강조사항에 계속기업 문구가 있으면 코드가 바로 확인 필요. 아니면 사업보고서 "회계감사인의 감사의견 등" 표(계속기업 관련 중요한 불확실성 열)를 AI가 읽고 인용과 함께 판단하며, 인용이 원문에 없으면 확인 불가. 감사의견 표를 원문에서 찾지 못해도 확인 불가
- 특수관계자 거래: 연결 주석의 당기 거래 표에서 매출 등·매입 등 합계 행을 AI가 인용과 함께 추출하고(합계는 행의 맨 오른쪽 칸일 때만 인정), **매출 또는 매입 합계가 연결 매출액의 30% 이상이면 확인 필요**, 둘 다 30% 미만이면 이상 없음, 한쪽이라도 확인하지 못하면(다른 쪽이 30% 미만이어도) 확인 불가. **30%는 이 도구의 참고 기준이며 법적 기준이 아니라는 안내를 화면에 붙인다**. 금액이 큰 거래 상위 3개(회사명이 값과 같은 칸에 있는지 코드가 확인한 것만)도 보여준다
- 특수관계자에 대한 **자금 대여금과 지급보증**: 같은 AI 호출에서 인용과 함께 추출해 금액과 원문 링크만 보여주고 판정하지 않는다. 금액은 원문 표기 그대로(외화는 환산하지 않음, 예: "RMB 701백만"). AI가 없다고 하면 "해당 없음"(누락됐을 수 있음 안내), 찾았지만 원문과 대조하지 못하면 "확인 불가"
- 항목마다 주석 ⓘ(의미·왜 중요한가=AI 작성, 근거=코드가 저장한 원문 링크)와 섹션 맨 위 한 줄 요약(AI 작성)을 붙인다
- 회계 이슈의 주석 기반 추출(계속기업·특수관계자)은 지금처럼 DART 원문(document.xml)을 쓴다. PDF로 바꾸지 않는다(6장 정할 것 3)

조건과 예외 (AI 해석: 외부 환경·SWOT·과제·기여, Phase 7-B → 8-C에서 입력만 바뀜)
- **AI 호출**: 7-B의 3번(① 외부 환경 ② SWOT + 종합 한 줄 평가 ③ 과제·역량·직무별 기여)은 그대로 두고, PDF 서술 추출 3번을 더한다( ⓐ 업계 위치·주요 고객·위험 요인 ⓑ 경영진단 ⓒ 연구개발·투자·신사업). 리포트 1건 AI 호출은 **최대 14회**(재시도 제외). 앞 단계가 실패하면 뒤는 "앞 단계 실패", [다시 시도]는 실패한 것만
- **AI에 넘기는 자료**: 사업의 내용은 **올린 PDF의 섹션 텍스트**로 바꾼다(지금은 DART 원문의 사업의 개요·원재료 및 생산설비·기타 참고사항). 6-A 사업부문·해외 매출 비중, 코드 계산 결과(핵심 지표·신호등·실적 추이·재무비율·현금흐름·최근 실적·회계 이슈 판정·**4장 체크리스트 판정**), ECOS 환율·기준금리, 최근 3개월 DART 공시 목록. **경쟁사 비교 결과(`calc:competitors`)는 넘기지 않는다**. **네이버 기사는 넘기지 않는다**
- SWOT·과제에는 위 자료에 더해 **검증을 통과한** PDF 추출 결과(업계 위치 인용, 경영진단 요약, 3장 요약, 위험 요인)를 근거 키로 넘긴다(예: `pdf:position`, `pdf:mda`, `pdf:focus`, `pdf:risks`, `check:one_off` 등)
- **근거 검사·숫자 검사·5 Forces 강도·민감도 방향·공시 주제** 규칙은 7-B와 같다(목록에 없는 키 버림, 근거 없는 항목 버림, 넘긴 자료에 없는 숫자가 든 문장 버림, 버린 문장 수를 맨 위에 안내)
- **기존 리포트**: PDF 없이 만든 리포트는 PDF 기반 섹션에 "PDF 없이 만든 리포트입니다. 새로 만들면 표시됩니다"를 보여주고, PDF를 나중에 올려 채우는 기능은 두지 않는다. 기존 7-B 결과(SWOT·과제)는 그대로 보인다

조건과 예외 (5장 과제·직무별 기여)
- AI는 넘겨받은 분석 결과 안에서만 과제를 뽑고, 근거가 되는 섹션이 없는 과제는 만들지 않는다
- **자기소개서 문장은 쓰지 않는다.** 역량·기여는 "무엇을 볼 수 있는가" 수준의 짧은 아이디어로 쓴다
- 근거가 부족해 과제 3개를 못 뽑으면 뽑은 만큼만 보여주고 "근거 부족"을 표시한다. 직무별 기여 표도 남은 과제만큼만 행을 만든다
- 같은 AI 호출(③)의 한 줄 요약은 5장 "회사 과제" 맨 위에 둔다
- 근거 섹션 목록(코드가 정함): SWOT 약점, SWOT 위협, 공시 주제 1~3, 핵심 지표 신호등, 경제 환경 민감도, 현금흐름 패턴 + **(새로) 4장 체크리스트 중 "확인 필요" 항목, 2장 경영진단, 4장 위험 요인**. AI가 이 밖의 키를 고르면 버린다
- 자기소개서식 표현(저는·제가·입사·지원 동기·지원하·기여하겠·하겠습니다·열정·포부 등)이 든 줄은 코드가 버린다
- 안내 "분석 기반 제안입니다. 회사의 공식 인재상이 아닙니다."는 회사 과제와 직무별 기여 각각의 섹션 제목 바로 아래에 둔다

### 5대 재무비율

| 그룹 | 지표 | 계산식 |
| --- | --- | --- |
| 수익성 | 영업이익률 | 영업이익 ÷ 매출액 |

| | ROE | 지배주주 순이익 ÷ 평균 지배주주 자본 |
| | ROA | 당기순이익 ÷ 평균 총자산 |
| 안정성 | 부채비율 | 부채총계 ÷ 자본총계 |
| | 유동비율 | 유동자산 ÷ 유동부채 |
| | 이자보상배율 | 영업이익 ÷ 이자비용 |
| 활동성 | 총자산회전율 | 매출액 ÷ 평균 총자산 |
| | 매출채권회전율 | 매출액 ÷ 평균 매출채권 |
| | 재고자산회전율 | 매출원가 ÷ 평균 재고자산 |
| 성장성 | 매출액증가율 | (당기 매출 − 전기 매출) ÷ 전기 매출 |
| | 영업이익증가율 | (당기 영업이익 − 전기 영업이익) ÷ 전기 영업이익의 절댓값 |
| | 총자산증가율 | (당기 총자산 − 전기 총자산) ÷ 전기 총자산 |
| 시장가치 | PER | 시가총액 ÷ 지배주주 순이익 |
| | PBR | 시가총액 ÷ 지배주주 자본 |

- "평균"은 (기초 + 기말) ÷ 2. 첫 연도는 기말 값만 사용하고 표시
- 분모가 0이거나 음수여서 의미 없는 경우(예: 적자일 때 PER) 숫자 대신 "해당 없음(적자)" 표시
- 시가총액은 리포트 생성 시점의 가장 최근 거래일 기준이며 **보통주 기준**이다. 화면에 "보통주 기준"과 "우선주가 있는 기업은 포털 시가총액보다 작게 나올 수 있음" 안내, 기준일을 표시한다
- PER·PBR의 분모는 기준 사업연도의 지배주주 순이익·자본(별도 기준 기업은 당기순이익·자본총계). 포털은 보통 최근 4개 분기 이익을 써서 값이 다를 수 있다는 안내를 붙인다. 시세가 없는 기업은 세 칸 모두 "시세 없음"
- PER·PBR·시가총액은 **분석 기업만** 계산해 부록 D에 보여준다(경쟁사 평균 대비 높음·낮음은 보이지 않음)
- 주가 차트: 상장주식수가 하루 사이 2배 이상 늘거나 절반 이하로 줄면 그 기업에 "액면분할·병합 등으로 왜곡됐을 수 있음"을 표시, 첫 거래일이 기간 시작보다 10일 넘게 늦으면 그날을 기준(=100)으로 하고 그렇게 표시. 주가 수집이 실패하면 생성 단계 "주가 수집" 실패(리포트 저장 안 함, [다시 시도]), 분석 기업 시세가 없으면 부록 D에 "시세 없음"

### 듀퐁 분석

ROE = 순이익률 × 총자산회전율 × 재무레버리지(평균 총자산 ÷ 평균 자본)

| 일회성 이익 | N년 또는 최근 누적 기간의 지배주주 순이익이 영업이익보다 크다(영업 밖에서 이익이 났다), 또는 영업이익은 적자인데 순이익은 흑자 | 순이익 ≤ 영업이익 | 영업이익·순이익 자료 없음 |
| 현금흐름 | N년 영업현금흐름이 적자, 또는 영업현금흐름이 당기순이익보다 작다(이익만큼 현금이 들어오지 않음) | 영업현금흐름 흑자이고 순이익 이상 | 현금흐름 자료 없음 |
| 부채·이자 | 부채비율 200% 초과 또는 전년보다 50%p 넘게 상승(신호등 "위험"과 같은 기준), 또는 이자보상배율 1배 미만 | 그 밖 | 부채비율 자료 없음 |
| 고객·제품 의존도 | 최대 부문(품목) 매출 비중 50% 이상(코드 계산), 또는 회사가 밝힌 주요 고객 매출 비중 30% 이상(검증된 인용 안의 숫자) | 둘 다 기준 미만 | 부문 비중을 확인하지 못함 (고객 문장이 없으면 고객 쪽은 "언급 없음"으로 두고 부문 비중만으로 판정) |
| 회사가 밝힌 위험 요인 | (판정하지 않음, 상태 "참고") | | |
| 회계 이슈 | 4개 항목 중 하나라도 확인 필요 | 4개 모두 이상 없음 | 그 밖(하나라도 확인 불가) |

- **"확인 필요"·"확인 불가"에는 항상 이유를 함께 보여준다**(체크리스트 한눈에 표와 각 섹션 맨 위 모두). 형식은 "확인 필요: {무엇이 걸렸는지 쉬운 말}({숫자})". 이유는 코드가 아래 문장 틀로 만들고 숫자는 저장된 계산 결과를 숫자 표시 규칙대로 쓴다. AI가 쓰지 않는다. 기준이 여러 개 걸리면 이유를 모두 쉼표로 이어 쓴다
- **이유는 "나쁘다"가 아니라 "무엇을 봐야 하는지"로 쓴다.** 특히 최대 부문 비중 50% 이상은 위험이 아니라 **집중도**이므로 "한 사업에 집중됨"으로 쓰고, 화면에 "집중 자체가 문제는 아니며, 그 사업의 업황에 실적이 크게 좌우될 수 있다는 뜻입니다" 안내를 붙인다

| 항목 | 걸린 기준 | 이유 문장 틀 (예시) |
| --- | --- | --- |
| 일회성 이익 | 순이익 > 영업이익 | 확인 필요: 영업 밖에서 생긴 이익이 큼(2026년 1~6월 순이익 134.2조 원 > 영업이익 98.2조 원) |
| | 영업이익 적자·순이익 흑자 | 확인 필요: 영업은 적자인데 순이익은 흑자(영업이익 −7.7조 원, 순이익 2.1조 원) |

| | 전년보다 50%p 넘게 상승 | 확인 필요: 부채비율이 1년 새 크게 오름(140.0% → 195.2%, +55.2%p) |

- 이상 없음에도 짧은 이유를 붙인다(예: "이상 없음: 영업현금흐름 53.4조 원 ≥ 순이익 47.2조 원")
- 주요 고객 매출 비중은 인용에 있는 숫자를 코드가 읽는다(인용에 % 숫자가 없으면 "비중 언급 없음")

### 최근 실적 박스

- **어느 보고서인가**: 5년 추이의 마지막 사업연도(N) 다음 해(N+1)의 반기 또는 3분기 보고서. 3분기가 있으면 3분기, 없으면 반기. 해당 기간이 아직 끝나지 않았거나(반기는 6월 말, 3분기는 9월 말 이후부터) 보고서가 제출되지 않았으면 박스를 생략하고 "아직 제출된 반기·3분기 보고서가 없습니다"를 표시 (1분기와 이미 사업보고서에 포함된 연도의 보고서는 쓰지 않음)
- **누적 기준**: 반기는 1~6월, 3분기는 1~9월 누적 값을 전년 같은 기간 누적 값과 비교한다 (3개월 값이 아니라 누적). 화면에 기간을 함께 표시한다. 12월 결산 기업을 가정한다 (6장 확인 필요 6)
- **항목**: 매출액, 영업이익, 영업이익률(영업이익 ÷ 매출액), 지배주주 순이익
- **증감**: 매출액·영업이익·지배주주 순이익은 증감률 = (당기 누적 − 전년 동기 누적) ÷ |전년 동기 누적|. 영업이익률은 %p 차이. 분모가 0이면 "해당 없음"
- **기준**: 5년 추이와 같은 연결/별도 기준 (별도면 지배주주 순이익은 당기순이익으로 대신하고 표시)
- **넣지 않는 것**: ROE·회전율처럼 1년 기준으로 읽는 지표, 누적이 아닌 3개월 값
- 단위는 억 원, 출처는 해당 보고서 접수번호와 원문 링크

### 기업 개요 보조 지표 (직원은 1장 주력 사업, 연구개발비는 3장 연구개발)

- 연구개발비 비중 = 연구개발비 ÷ 매출액 (최근 사업연도, 비율은 소수점 첫째 자리 %)
- 연구개발비 금액은 사업보고서에서 AI가 추출한 값이므로 "AI 추출" 표시 + 원문 링크를 붙이고, 비중은 코드가 계산한다
- 연구개발비 기재가 없거나 매출액이 0이면 "자료 없음"으로 표시한다
- 직원 수·평균 근속연수·평균 급여는 DART 값을 그대로 보여주고 계산하지 않는다. 사업보고서 기준(보통 별도 법인)임을 값 옆에 표시한다

### 경제 환경 민감도

- 수출 비중(사업보고서에서 추출)과 환율 1년 추이를 함께 보여준다
- "환율 10% 상승 시" 영향은 **방향과 이유만** 쓴다 (예: "수출 비중 70%로 매출에는 긍정적, 원재료 수입이 많아 원가에는 부정적"). 금액 추정은 하지 않는다

### 자기소개서에 쓸 숫자 모음 (5장, 2026-11-03 추가·방향 조정)

- **새 숫자를 만들지 않는다.** 리포트에 이미 저장된 계산 결과·검증된 추출값만 코드가 골라, 정해진 틀의 **한 줄 사실**로 만든다. AI 호출 없음, 저장값 추가 없음(화면에서 저장된 결과로 만든다. 그래서 기존 리포트에도 바로 보인다)
- 숫자 표시는 0장 "숫자 표시 규칙"을 그대로 따른다(비율 소수 첫째 자리 %, 증감은 +/− 부호, 금액은 카드처럼 조 원)
- 줄마다 **출처 링크**(해당 값의 원문 링크: 사업보고서·반기/3분기보고서·주식시세 기준일)와 기준(연결/별도)을 붙인다. AI가 추출한 값(원문 인용 검증을 통과한 것만)은 줄 끝에 "(AI 추출)"
- 9번은 경쟁사 비교를 없애면서 "시가총액 순위"에서 "시가총액"으로 바꿨다(6장 정할 것 6, 확정). 회사가 밝힌 점유율처럼 인용 문장 속 숫자는 넣지 않는다(문장 전체를 1장 업계 위치에서 본다)
- 값이 없거나 "해당 없음"(적자·전기 자료 없음 등)·"시세 없음"·"확인 불가"인 항목은 **그 줄을 넣지 않는다**(자료 없는 줄을 자기소개서 재료로 보여주지 않음). 뺀 항목은 목록 아래 작은 회색 글씨로 "제외: 연구개발비 비중(자료 없음)"처럼 이유와 함께 표시
- 순서와 문장 틀은 고정한다. 해석·평가 표현("우수한", "업계 최고")은 넣지 않는다. 연도는 기준 사업연도(N), 최근 실적은 해당 보고서 기간

| 순서 | 항목 | 문장 틀 (예시) | 가져오는 값 | 출처 |
| --- | --- | --- | --- | --- |
| 1 | 매출액 | "2025년 매출액 ○○.○조 원" | 재무 수집(N년) | N년 사업보고서 |

- 항목을 늘리거나 줄이는 것은 이 표만 고친다(문장 틀·출처 규칙은 같음)

## 6. 확인 필요 (개발 준비 단계에서 확인)

### 정할 것 → 확정 (2026-11-03 방향 조정, 11개 모두 추천안대로 사용자 확정)

1. **PDF 확인 방법**: 코드가 표지에서 ① 글자 읽힘 ② 보고서 종류 ③ 정식 회사명 ④ 사업연도 기간을 확인해 하나라도 다르면 거절, ⑤ 요약재무정보의 매출액을 DART 값과 대조해 다르거나 못 찾으면 경고만 (F2)
2. **PDF를 안 올렸을 때**: 사업보고서 PDF 필수, DART 원문으로 자동 대체하지 않음. 반기/3분기는 선택 (F2)
3. **PDF로 바꿀 범위**: 새 서술 섹션(업계 위치·경영진단·연구개발·투자·신사업·위험·주요 고객)과 외부 환경·SWOT·과제의 "사업의 내용" 입력만 PDF로. 이미 검증된 DART 원문 추출(사업부문·해외 비중·연구개발비 금액·이자비용·계속기업·특수관계자)은 그대로 둔다
4. **PEST·경제 환경 민감도**: 요청 목록에는 없지만 부록 A 거시에 남긴다(AI 호출 추가 없음, 기존 `pest`·`macro` 코멘트 보존)
5. **PDF 원본 보관**: 원본은 저장하지 않고 읽은 섹션 텍스트·쪽 범위·해시만 저장(나중 Supabase 용량·개인 파일 관리 부담을 줄임). 인용 링크는 DART 공시뷰어 원문
6. **숫자 모음 9번**: "시가총액 순위" → "시가총액(분석 기업, 기준일·보통주)"
7. **AI 호출 수**: PDF 서술 추출 3번 추가(ⓐ 업계 위치·주요 고객·위험 요인 ⓑ 경영진단 ⓒ 연구개발·투자·신사업), 리포트 1건 최대 14회. 섹션당 입력 12,000자 상한
8. **반기/3분기 PDF 쓰임**: 3장(연구개발·투자·신사업)의 "최근 보고서에서 바뀐 점" 보충에만. 경영진단은 반기·분기보고서에 기재하지 않는 항목이라 쓰지 않음. 3분기보고서도 받는다(최근 실적 박스와 같은 규칙)
9. **4장 판정 기준값**: 3장 "4장 체크리스트 판정" 표(순이익 > 영업이익, 영업현금흐름 < 순이익, 부채비율 200%·+50%p·이자보상배율 1배, 최대 부문 50%·주요 고객 30%)
10. **PDF 없이 만든 기존 리포트**: 그대로 열리고 PDF 기반 섹션은 "PDF 없이 만든 리포트" 안내. 나중에 PDF를 올려 채우는 기능은 두지 않음
11. **PDF 읽기 라이브러리**: Phase 시작 시 SK하이닉스 사업보고서 PDF로 pypdf(BSD)와 pdfplumber(MIT)를 비교해 한글·쪽 번호가 바르게 나오는 쪽을 고른다(PyMuPDF는 AGPL이라 후순위) → **pdfplumber로 확정(2026-11-03)**. 둘 다 한글은 같게 읽지만 pypdf는 표를 쪽 맨 끝으로 보내 섹션 경계가 틀어진다. 책갈피는 pdfplumber에 딸린 pdfminer로 읽어 라이브러리는 하나만 쓴다
12. **(사용자 추가) 4장 이유 표시**: "확인 필요"마다 이유를 함께 보여준다. 최대 부문 비중 50% 이상은 위험이 아니라 집중도이므로 "확인 필요: 한 사업에 집중됨(DRAM 77.1%)"처럼 설명한다 (3장 "4장 체크리스트 판정" 이유 문장 틀)
